# 二果园足球预测系统 Headless Prediction Engine

## 目标和边界

YY-CORE Desktop UI 自 2026-10-05 起冻结，不再修复、扩展或增加界面功能。日常操作由 Codex 在本地调度现有 Python 程序完成。Codex 是流程协调者，不是 R3 概率模型；任何概率都必须由登记的正式模型实际执行产生。

固定生命周期：

```text
Prediction → Lock → Result → Evaluation → Database
```

预测与赛果必须按 `prediction_id` 关联。每一步保留时间、数据来源、模型版本和状态；未完成步骤不得用占位结果伪装成功。

## 可用入口与当前状态

- `python -m production.launcher`：现有生产试运行命令行入口，读取 `config/production.yaml`，通过 `ProductionRunner` 执行已实现的 fixture/data/model readiness 与预测流程，并在启用记录时追加写入 `data/trial_prediction_records.sqlite`。
- `python -m production.launcher --bridge-input <CORE_DATA_PACKET_V1.json>`：现有 Research Bridge 数据包入口；CORE 会重新校验实体、PIT、快照和 readiness，再由自己的模型执行器运行可用模型。
- `TrialRecordStore` 的 SQLite 触发器禁止更新或删除预测记录。该特性保证保存后的原记录不可被静默改写，可作为预测冻结依据。

当前不是完整每日生产闭环：配置模式仍是 `TRIAL`；最终 OOS/生产晋级门禁仍未完成；试运行记录没有已验证的正式赛果录入和自动评分接口；生产与研究也尚未在独立代码/配置/可变存储根上实施硬隔离。当前状态不得表述为 `LIVE_PRODUCTION_READY`。

## 每日操作规程

### Prediction

1. 先读取用户输入与其预测时点，不推测缺失比赛、赔率或阵容。
2. 只调用 `production.launcher` 或现有 Research Bridge，再由 CORE 运行已登记模型。
3. 必须通过现有 fixture、数据快照和 PIT/readiness 检查；缺项原样显示 BLOCKED/UNAVAILABLE。
4. 只把程序实际返回的模型概率纳入结果。Codex 不补概率、不平均模型输出，也不将开发期结果冒充正式结果。

### Lock

保存成功后立即记录 `prediction_id`、冻结时间、模型/工件版本、输入快照 ID 与输出哈希。现有试运行记录是追加式、不可 UPDATE/DELETE；如果输出没有被持久化或无法重新核验其身份，则不得报告已锁定。

### Result

仅在比赛结束后录入赛果，并保留官方或其他经授权来源的 URL、来源名称、抓取时间、比赛标识和核验状态。不得把目标比赛结果反馈至它自己的赛前数据快照。当前尚无已验证的生产赛果录入命令；在其实现前，只能报告该步骤尚未完成，不得手工改写历史预测记录。

### Evaluation

按正式指标定义，用锁定概率和已核验赛果计算评分；每条评分同时引用 `prediction_id`、模型版本、实际结果来源、评分版本与评分时间。现有历史 OOS/回测模块不等价于生产预测的赛后评分账本。当前该账本未完成，不能声称生产预测已自动评分。

### Database

原预测永远保持不变。实际赛果和评分通过独立、追加式事件记录关联到原预测；重复导入必须幂等并产生审计轨迹。当前暂无统一完成上述生命周期的数据库写入接口，不得未经实现与验证而扩展现有预测表用途。

## PRODUCTION 与 DEVELOPMENT 隔离

### PRODUCTION

- 使用经过批准的冻结代码、配置、模型工件和特征定义。
- 允许读取已审核的历史数据与快照；允许向指定的生产预测、赛果和评估账本追加记录。
- 禁止临时改代码、训练、调参、覆盖模型工件或写入研究实验数据。
- 未通过时间隔离 OOS、概率校准、版本审计与晋级审核的新模型不得载入。

### DEVELOPMENT

- 使用独立的代码工作区、配置、训练/实验工件、临时数据库和回测输出。
- 可研究、训练、调参和回测；结果必须标注开发状态，不影响生产模型注册、工件或预测账本。
- 只有经过独立时间隔离验证与审批的版本才能被提升到 PRODUCTION。

### 现状限制

仓库当前仅有一个源代码工作区。`config/production.yaml` 为 `TRIAL` 配置，代码和若干数据/工件仍位于同一个项目树；尚无强制的独立生产发布目录和开发目录。因此目前只具备操作策略，尚未具备运行时强制隔离。没有隔离之前，Codex 不得同时在该工作区执行生产预测和开发改动；也不得宣称已完成 Headless 生产转换。

## 解除阻断所需工作

1. 建立只读的生产代码/配置/模型发布根，并建立独立开发工作区。
2. 将生产预测记录与开发数据库/工件物理隔离，记录发布哈希与模型晋级清单。
3. 增加赛后赛果导入和来源审计接口，禁止改写原预测。
4. 增加预测冻结清单、幂等赛果关联、自动评分和追加式数据库更新。
5. 对完整生命周期做离线集成验证及回归验证后，再评估日常生产启用状态。

这些工作不得改动 V5.1 展示契约、已有模型数学、PIT 或 readiness 门槛来规避缺失能力。

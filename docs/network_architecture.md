# Network foundation

`CoreNetworkClient` is the shared synchronous HTTPX client boundary. Providers resolve endpoint IDs from `ExternalSourceRegistry`; unknown endpoints, unknown hosts, empty responses, invalid JSON, future source timestamps, failed authentication, and retry exhaustion fail explicitly. HTTPX connection pooling is shared, TLS verification is always on, and `AUTO` honors current Windows routing (including an already active TUN route) and HTTPX environment proxy variables. `DIRECT` disables environment proxy use. `EXPLICIT_PROXY` uses the configured HTTP(S) proxy. SOCKS is rejected unless separately supported and tested. CORE does not inspect VPN processes or start, modify, or bypass networking.

No production provider URL is configured because no legal endpoint or provider documentation was supplied. URLs are never guessed. The registry currently has no production source records; therefore a production preflight fails closed until required sources are registered with source-specific health endpoint, response validator, source timestamp field, authentication policy, timeout, retry, cache, rate limit, and schema version.

Preflight checks actual configured critical/required sources rather than unrelated websites. A source needs a registered `health` endpoint, response schema validator, and declared timestamp field. `ProductionNetworkGate` allows production continuation only on `PASS`; an explicit offline test mode is development-only. `refresh_network_status` reruns source checks without restarting CORE.

Cache identities include source ID, endpoint ID, canonical parameter hash, and schema version. A cache payload is eligible only when its source timestamp is at or before the prediction time. Audit rows record request timing, status, cache use, latency, content hash, schema version, and outcome; credentials are not part of the audit schema. API tokens are loaded only from declared environment variables.

The client uses bounded retry and source pacing. It retries configured transient statuses (429, 502, 503, 504) and transport failures, honors bounded `Retry-After`, and does not retry authentication, client, or schema errors. Connect/read/pool timeouts are configured; the total elapsed duration is checked after HTTPX returns, so a slow streaming response can exceed the nominal total before this synchronous client regains control. A stricter cancellable end-to-end deadline remains a production limitation.

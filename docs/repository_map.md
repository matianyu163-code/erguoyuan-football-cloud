# Repository map

| Module | Responsibility | Main entry points | Public boundary |
|---|---|---|---|
| `contracts/` | Immutable audit and prediction records | `ModelPrediction`, `CorePrediction` | Pydantic contracts |
| `data/` | DuckDB-backed records and point-in-time snapshots | `Store`, `SnapshotService` | Snapshot and persistence schemas |
| `data/real_bootstrap.py`, `data/real_quality.py`, `data/bootstrap.py` | Pinned OpenFootball RAW → STAGING → CANONICAL import and measured quality | `RealDataWarehouse`, CLI, `assess_real_data` | Independent Phase 8 real-data tables; no backdated OOS |
| `data/external_providers.py` | Authorized football-data.org boundary and StatsBomb local catalogue availability | `FootballDataOrgProvider`, `StatsBombOpenDataProvider` | Explicit unavailable states without credentials/data |
| `data/temporal.py` | Data-class-specific event, snapshot, market and forecast PIT eligibility | `TemporalEligibilityPolicy`, `TemporalEligibilityValidator` | Immutable historical events are separate from mutable snapshots |
| `data/kickoff_enrichment.py`, `data/kickoff_provider_import.py` | Additive verified UTC kickoff enrichment and review queue | `KickoffEnrichmentLayer`, provider CLI | Never edits pinned OpenFootball RAW/CANONICAL kickoff fields |
| `output_contract/` | CORE_OUTPUT_V2 intermediate result and preview | `CanonicalPredictionResult`, `BaseOutputAdapter` | No Phase 11 selection or stakes |
| `gates/phase8_readiness.py` | Phase 9 fail-closed readiness | `assess_phase9_gates` | Measured gate report |
| `input/` | Text, batch, screenshot and match resolution | `DailyService`, parsers | `MatchRequest` |
| `knowledge/` | Phase 13.1 versioned offline team/competition identity seed and conservative alias resolution | `TeamResolver`, `CompetitionResolver`, `GlobalKnowledgeResolver` | Identity only; no fixture, data provider, or prediction |
| `knowledge/entities/` | Phase 13.6 universal team/competition hint parsing, dimension-safe identity, opt-in league-scoped discovery and persistent verified-entity catalogue | `UniversalTeamResolver`, `OpenLigaDBTeamDiscovery`, `VerifiedEntityStore`, `entity_probe` | Default offline; gender/age/squad/provider ID conflicts fail closed; verified team is not a verified fixture |
| `web_research/` | Phase 13.2 planning and Phase 13.4 opt-in registered JSON provider connectivity, routing, freshness, conflict, evidence, cache and audit | `QueryBuilder`, `ProviderRouter`, `LiveResearchFetcher`, `EvidenceStore` | All HTTP through `CoreNetworkClient`; no endpoint guessed and no prediction data injection |
| `research/` | Phase 13.3 PIT match research package and Phase 13.4 optional live orchestration with official fixture verification | `MatchResearchOrchestrator`, `MatchResearchPackage`, `DataQualityEvaluator` | `fetch_live=False` by default; unverified fixture uses research session ID; no model or output-contract calls |
| `research/canonical_match.py`, `historical_match_repository.py`, `historical_data_acquirer.py` | Phase 14.1 canonical fixture identity and UTC/PIT historical result query/acquisition contracts | `CanonicalMatchIdentity`, `HistoricalMatchRepository`, `HistoricalDataAcquirer` | Final results require provider evidence; current acquirer wraps the existing one-response season endpoint |
| `research/production_match_data.py`, `production_match_pipeline.py`, `model_input_validator.py`, `pipeline_execution_record.py` | Phase 14.1 fail-closed data-only pipeline, per-stage audit, sample quality, model input readiness and dry-run plan | `ProductionMatchPipeline`, `ProductionMatchDataBundle`, `PipelineExecutionStore` | Never calls a prediction model; LIVE path currently limited to configured OpenLigaDB EPL team bindings; REPLAY requires persisted as-of evidence and is blocked pending implementation |
| `jc_verification/` | Phase 14.4-JC2 provider-backed JC status, canonical fixture matching, SQLite daily slate cache, and evidence-tier resource plans | `JCMatchVerifier`, `JCProviderRegistry`, `JCMatchCache`, `JCResourceScheduler` | No JC source is currently configured; default result is `UNKNOWN / SOURCE_UNAVAILABLE`; provider adapters must use `CoreNetworkClient`; no prediction or output-contract changes |
| `match_source/` | Phase 14.4-JC3 deterministic input provenance classification and append-only source audit | `MatchSourceClassifier`, `MatchSourceAuditStore`, `MatchSourceType` | Explicit user JC declarations bypass official lookup as `USER_CONFIRMED`; ordinary requests remain `AUTO_DISCOVERY`; research fixtures bypass JC status lookup; source metadata does not alter model probabilities |
| `research/production_data_probe.py` | Phase 14.1 command-line probe with text and JSON diagnostics | `python -m erguoyuan_football.research.production_data_probe` | Explicit UTC cutoff, no prediction, no V5.1 output |
| `research/live_data/` | Phase 13.5 keyless Tier B OpenLigaDB adapter, exact fixture check, persisted real results, derived recent form and source-backed model readiness | `OpenLigaDBProvider`, `LiveResearchService`, `LiveDataReadinessGate`, `live_probe` | All HTTP through `CoreNetworkClient`; league and team bindings are reviewed configuration; readiness never runs prediction models |
| `research/samples/` | Phase 13.6 PIT historical sample repository, cross-provider deduplication, source-conflict exclusion, lineage and direct/competition/comparable/prior hierarchy | `SampleRepository`, `SampleBuilder`, `SampleHierarchy` | Existing evidence is read without a second match database; no sample category is promoted to direct observations |
| `research/provider_coverage_profile.py`, `global_provider_registry.py`, `coverage_resolver.py`, `provider_merge.py`, `multi_provider_fetcher.py`, `coverage_matrix.py` | Phase 13.7 capability evidence, global provider routing, bounded fetch attempts, conflict-safe merges, and coverage reporting | `CoverageResolver`, `MultiProviderFetcher`, `build_coverage_matrix` | Declarations remain UNVERIFIED until evidence-backed checks; unsupported categories remain explicit |
| `research/live_data/openligadb_directory.py`, `football_data_org_directory.py`, `global_registry_factory.py`, `config/phase13_7_openligadb.yaml` | Public multi-competition team/competition directories; verified live scopes and audited directory evidence | `OpenLigaDBDirectoryProvider`, `FootballDataOrgDirectoryProvider`, `build_global_provider_registry` | OpenLigaDB reviewed German scopes; football-data.org public competition directory only |
| `research/live_data/model_readiness.py`, `config/phase13_6_model_readiness.yaml` | Per-model fit-input thresholds and grouped readiness, replacing Phase 13.5's global 40-match gate | `ModelReadinessEvaluator`, `LiveDataReadinessGate` | Uses real model IDs and current ModelConfig defaults; does not fit or predict |
| `models/` | Trainable base models and model lifecycle | `ModelRunner`, `ModelRegistry` | `BaseFootballModel`, `ModelPrediction` |
| `prediction/` | Phase 14 model-specific sample adapters, readiness-gated fit/inference plans, isolated execution and append-only audit | `ModelExecutionPlanner`, `ModelExecutionEngine`, `ExistingModelExecutor`, `python -m erguoyuan_football.prediction.model_plan` | CLI is dry-run and fail-closed; no daily production prediction or V5.1 output |
| `models/dynamic_bayes/` | Sequential Bayesian Poisson state model | `CoreDynamicBayesianPoissonModel` | Model wrapper and inference adapter |
| `models/spi/` | CORE SPI-inspired global strength model | `CoreSPILikeModel` | SPI state and feature contracts |
| `models/opta_like/` | CORE hierarchical rating and xG-Elo-inspired model | `CoreOptaXGEloLikeModel` | Hierarchy and xG provenance contracts |
| `network/` | External-source registry, HTTP client, health, cache and audit | `CoreNetworkClient`, `run_network_preflight` | Network config and gate contracts |
| `external/opta/` | Lawful Opta provider boundary | `OptaProvider` | Provider protocol; unavailable without authorized source |
| `external/market.py` | Authorized odds adapter, routed through `CoreNetworkClient` | `CoreNetworkMarketProvider` | Market quote provider result |
| `markets/` | Canonical odds, PIT market snapshots, de-vig, consensus, settlement and implied goals | `MarketEngine`, `MarketDataPipeline` | Market schemas and quote lineage |
| `markets/identity.py` | Verify provider event teams, competition and kickoff against one catalog fixture; audit orientation | `MarketEventBinder` | `ProviderEventIdentity`, `EventBinding` |
| `models/historical_market_bayes.py` | Market-anchored historical goal model | `HistoricalMarketBayesianPoissonModel` | `HISTORICAL_MARKET_BAYESIAN_POISSON_V1` |
| `ml/` | Frozen PIT ML features, two official tree wrappers, native artifacts, OOS backtest, benchmarks and ablations | `MLFeatureBuilder`, `MLFeatureStore`, `CoreXGBoostModel`, `CoreCatBoostModel`, `MLWalkForwardBacktester` | `MLFeatureVector`, `MLDataset`, `ModelPrediction` |
| `backtesting/market_engine.py` | Horizon-separated market and historical-market OOS evaluation | `walk_forward_market_bayes`, `evaluate_market_baselines` | Market baseline reports |
| `backtesting/` | Rolling out-of-sample evaluation | `walk_forward_split`, `evaluate_oos` | OOS metrics |
| `backtesting/date_safe_oos.py` | Real daily-batch walk-forward for immutable event results when exact historical UTC is absent | `run_real_date_safe_oos` | No same-day updates, market, lineup or external forecasts |
| `backtesting/real_oos_runner.py`, `real_oos_matrix.py`, `phase8_2_store.py` | Phase 8.2 registry-driven real OOS, status/lineage store, and null-aware prediction matrix | `UnifiedRealOOSRunner`, `RealOOSPredictionMatrix` | DATE_SAFE_BATCH and persisted REAL OOS only |
| `backtesting/real_ml_features.py`, `real_ml_oos.py` | Verified base-OOS features and chronological XGBoost/CatBoost OOS | `RealDateSafeMLDatasetBuilder`, `RealMLOOSRunner` | NO_MARKET, nested OOS, native artifact cache |
| `backtesting/golden_selector.py`, `golden_lock.py` | Phase 15 blind candidate CSV, human-editable JSON approvals, versioned 100-match lock and append-only selection audit | `GoldenCandidateSelector`, `python -m erguoyuan_football.backtesting.golden_lock` | No UI; results omitted from review and locked manifests; incomplete or unverified candidates fail closed |
| `backtesting/phase9_candidate.py`, `phase8_2_audit.py` | Physically separated candidate features/labels/lineage and deterministic self-review | `Phase9CandidateBuilder`, `run_phase8_2_audit` | Final holdout locked; no META fitting |
| `meta/` | Phase 9 recursive OOS ancestry, dependency-aware no-market META, development calibration, separate META/calibrator manifests, disagreement diagnostics, CORE V2 adapter, promotion gate and audit | `PredictionLineageValidator`, `run_phase9_development`, `save_artifact`, `build_development_core`, `audit_phase9` | DATE_SAFE_BATCH, DEVELOPMENT_ONLY / NOT_PROMOTED; final holdout and market excluded |
| `context/` | Phase 10 PIT tournament state, standings, tie aggregation, fatigue availability, lineup/injury/player evidence, feature lineage, no-fit identity adjustment, audit and additive persistence | `ContextPipeline`, `ContextStore`, `python -m erguoyuan_football.context.run_phase10` | Real Phase 9 development CORE V2 only; `DEVELOPMENT_ONLY / NOT_PROMOTED`; incomplete external context remains null |
| `prediction_heads/` | Phase 11 effective CORE, OOS score-matrix source/readiness, outcome-mass reconciliation and play derivation | `EffectiveCoreProbabilityResolver`, `ScoreMatrixSourceSelector`, `ScoreMatrixReadinessAudit`, `OutcomeMassReconciler` | REAL OOS/PIT lineage; official handicap and HTFT need independent sourced evidence |

| `recommendation/` | Phase 6 de-vig price evidence, fair price and configurable development EV policy | `MarketValueEngine`, `RecommendationEngine`, `BetAdvice` | Missing price is UNAVAILABLE; synthetic price is test-only |
| `portfolio/` | Capped 400/100/20 experimental accounts and candidate/advice/settlement/weekly ledgers | `PortfolioEngine`, `weekly_metrics` | Cannot change selection or force stakes |

| `app/` | Phase 12 desktop shell, exact development-match resolution, existing report orchestration, append-only history and exports | `python -m erguoyuan_football.app` | Development review only; live production gate remains closed |
| `production/` | Phase 16 V1.0 trial launcher, fail-closed stage runner, audited diagnostic output, append-only trial records, immutable version registration, and SMART_BRIDGE request inbox/ready/result handoff | `python -m production.launcher`, `TrialRecordStore`, `UpdateManager`, `SmartBridgeIntake` | Source-file handoff is not a live Research Agent connection; CORE revalidates PIT and data before models, and unsupported readiness remains blocked |
| `output/v51/` | Frozen V5.1 output contract | schema, validator, renderer | Stable presentation structure |
| `gates/` | Production readiness gates | production network gate | Explicit PASS/FAIL decision |

Large data and artifact directories are intentionally outside the source map and must not be recursively scanned during routine feature work.

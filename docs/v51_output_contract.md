# V5.1 输出契约

项目：二果园足球预测系统。本文记录用户已确定的展示格式，底层模型升级不得改变该结构。
PHASE 2 已将本规范实现为 output/v51/schema.py、validator.py、renderer.py 和 Golden Test；PHASE 3 继续冻结该结构。
仅做字段校验与固定顺序 JSON 序列化，不提供真实预测样例，也不定义尚未明确的计算规则。

## 已确定的展示顺序与字段

### 1. 数据冻结时间

首先显示数据冻结时间。内部时间遵循 [审计契约](audit_contract.md) 的 UTC 约定。

### 2. 今日比赛筛选总表

字段顺序固定为：

编号｜比赛｜模型概率｜MDI｜URS｜Edge｜评级｜结论

### 3. 五类固定结果

以下顺序固定，每类有合格结果时各 1 组：

1. 胜平负二串一
2. 胜平负三串一
3. 总进球数
4. 半全场
5. 让球胜平负+普通胜平负混合二串一

某类不达标时在该类明确显示“无合格组合 / NO-BET”；全部不达标时同样明确显示该结论。
禁止为了凑齐五类而编造结果。不得自行设置合格阈值来生成候选。

每场完整字段，按以下顺序展示：

比赛编码｜联赛｜主队 VS 客队｜玩法｜投注方向｜竞彩赔率｜模型概率｜市场概率｜Edge｜URS｜置信等级

串关字段，按以下顺序展示：

联合命中概率｜组合赔率｜理论EV｜风险

### 4. 最后显示资金汇总

今日投入｜各组金额｜剩余滚存

## 待定义的计算及展示细节

- MDI、URS 的含义、输入、计算方法与阈值。
- 评级、置信等级、风险的定义与阈值，以及合格结果筛选规则。
- 总表模型概率的具体指向、市场概率的来源与去水方法、Edge 的计算口径。
- 串关联合命中概率的相关性处理、组合赔率与理论EV 的计算口径。
- 资金分配公式、初始资金、滚存规则以及 NO-BET 时的资金展示处理。
- 数据冻结时间的选取规则、界面显示时区、“今日”的日期边界、数字精度与缺失值显示方式。

以上内容未经明确不得自行补造。计算规则未定义或数据不足时，不得伪装成已有合格预测。
缺失概率和不适用数值的内部空值规则见 [审计契约](audit_contract.md)。
## PHASE 2 序列化约定

保留上阶段标签：“总进球数”对应本阶段的“总进球”，“投注方向”对应“预测方向”。
顶层顺序为冻结时间、总表、五类结果、今日投入、各组金额、剩余滚存。
每类为一个 ResultGroup，依次包含“结论”“比赛明细”“串关”。
串关始终保留四个固定字段；NO-BET 的比赛明细为空、串关值为 null，不编造结果。
各组金额按五类固定顺序保留键，未知金额为 null。
QUALIFIED 只表示调用方提供的已准入结果，渲染器不替代准入逻辑；DailyService 当前仅生成 NO-BET。
冻结时间序列化为 ISO UTC；未知值为 null，不使用 0 或均匀概率占位。
除此之外的精度和计算规则仍待定义。

tests/golden/v51/no_bet.json 为人工固定合成样例，columns.json 独立固定各层字段顺序。
Golden Test 和 validator 对栏目删除、重命名、字段顺序变化均失败。
这些测试验证格式，不能证明预测、评级或投注计算正确。
